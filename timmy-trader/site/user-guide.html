Start safely

Check your installed version.

This guide documents Timmy's current source interface. The website's current Debian download is 0.1.5, built October 19, 2026; newer controls described here may not appear in that package yet. Use the controls present in your installed version and do not assume a website guide means a feature is available in an older build.

  1. Install the Linux package from the Download page. Verify its SHA-256 checksum before installation.
  2. Launch Timmy from your application menu or the installed desktop launcher.
  3. Keep the execution target on Paper and mode on User. Check the Paper lane indicator: depending on profile settings, paper activity may arm at market open.
  4. Select Scan on the Market workspace and confirm the candle timestamp and source before using the results.
  5. Select a symbol to connect its chart, Decision Brief, and order plan.
First-run data can be synthetic.

If Timmy has no local candle file, it may create sample bars for the demo. Sample bars are not market data. Check the source and timestamps before relying on any price or signal.

Ctrl + K opens Quick Jump. F5 refreshes the data and scan state. Ctrl + R runs a decision cycle. A cycle can journal paper orders if the Paper lane is enabled; Live/Auto can submit only when every live gate is open.

Read a scan, not just a score

  1. RadarSee which symbols are moving and choose a ticker.
  2. ReadCheck signal score, scout urgency, action, price gates, reasons, and data quality.
  3. RiskReview entry, stop, target, reward/risk, size, and operational blockers.
  4. ActChoose a separate paper action or a fully gated live workflow.

The default data source is local CSV. Remote providers fetch delayed daily bars, not streaming quotes. Timmy refreshes data according to the selected provider and cache age; a failed refresh can leave older local candles in place.

Scanner text and category filters, sortable columns, and saved filters help narrow the visible rows. A saved filter stores its query, category, and minimum score. Applying one restores the shared minimum-score setting, which can affect plan eligibility. Applying a filter does not itself submit an order or enable broker access.

The selected-symbol chart can show the loaded candles, moving averages, volume, and planned entry/stop/target levels. Remote providers currently supply delayed daily bars. These levels are estimates from Timmy's model and do not ensure execution at those prices.

A signal marked “trade” or a high score is not an order approval. Timmy may block a plan for score, overextension, volatility, reward/risk, stale data, market session, cash, order size, cooldown, daily limits, broker response, or asset-class support.

Quality estimates need context.

The selected-symbol panel reports candle freshness, estimated gaps, duplicate timestamps, and invalid OHLC bars. Gap estimates use a fixed interval and do not know exchange calendars, weekends, or holidays. Inspect timestamps and the configured provider when flags appear.

Keep personal groups separate from trading scope

Select a symbol, create a personal group, then add the selected symbol to that group. Pin a symbol to filter the radar to pinned tickers. These are local organization tools. They do not replace the active trading watchlist, change generated trade-ready lists, or sync to Webull.

Paper and Live are different lanes

Paper: simulated and local

Paper Trade records simulated orders in Timmy's local journal and does not send orders to Webull. Portfolio positions, cash, and results are derived from this paper ledger and loaded candle prices. Simulated fills can differ from real execution.

The Paper lane can run on a schedule. Use Automation to check whether it is armed, and use Pause All Automation to stop scheduled cycles.

Live: real broker orders

Live requires a configured and checked Webull account, enabled live switches, supported instrument, fresh market/session state, a current eligible plan, risk limits, and broker approval. In User mode, Timmy asks before a manual submit. Auto mode locks manual execution controls.

The GUI requires a preview for the exact plan and account; it expires after three minutes and becomes invalid if the plan changes. The adapter's `WEBULL_REQUIRE_PREVIEW=1` setting is an additional hard block on submission. Only after validating the approved account's preview workflow should a local operator change that setting to permit submission; the GUI's exact-plan preview remains required.

Unknown is not rejected.

If a live order response is unknown, the broker may have received the order. Reconcile Webull order and position state before retrying. Stopping automation cannot cancel an order already sent.

Timmy defaults to Paper and User on launch, but saved settings and market-open automation preferences can affect scheduled paper activity. Confirm both the target and lane before each session. Auto-start for Live is off by default.

Set up Webull on your computer

  1. In Setup, enter the Webull OpenAPI App Key, App Secret, account ID, region, and endpoint locally.
  2. Select Verify Profile. If any value changes, verify the new values before saving.
  3. Save the verified profile locally. Timmy returns to Paper and clears the old account check.
  4. Open Broker and run Check Webull account. Confirm account identity and buying power before considering Live.
  5. Keep secrets, tokens, account IDs, passwords, and MFA codes out of screenshots, chats, and public files.

Account Check is a read operation. Preview is a broker rehearsal. Submit is the action that may place a real order. Read the FAQ and risk notes before using a live account.

Alerts and automation

Create local alerts for a symbol's price, scout score, or signal action. Alerts are evaluated after scans and saved in the local profile. Select a rule to enable/pause or remove it; select an event to acknowledge it. These rules do not send desktop notifications and never submit orders.

Automation schedules refresh and decision cycles. Enable Paper Automation enables the paper lane. Live/Auto is a separate route that can submit real orders when live switches and runtime checks pass. Review the Automation readiness panel and selected target before enabling any schedule.

Troubleshooting

  • Unexpected prices: check whether the active data is synthetic sample bars, an old CSV, or delayed remote daily data.
  • No executable plan: open Strategy or Health and review score, price, session, data, risk, and account blockers. Scanning is not the same as planning.
  • Live locked: verify the profile, run Broker Account Check, confirm the target/account, and resolve readiness issues. Do not bypass a guard to unlock a button.
  • Stale or failed refresh: verify network/provider availability and the newest candle timestamp. Older local data can remain visible after a fetch failure.
  • Second launch refused: close the active Timmy instance for that runtime home. Do not remove a lock while the process is running.

Current limits

Timmy focuses on stocks, ETFs, and index proxies. Crypto and futures can be configured for scouting, but live routing requires asset-specific account, data, sizing, and broker support to be verified. Options, event contracts, direct indexes, forex, CFDs, and unsupported instruments do not have a complete live execution path.

Timmy does not provide streaming quotes, integrated news or earnings analysis, guaranteed fills, or investment advice. Trading can lose money; you are responsible for reviewing each order and its risk.
