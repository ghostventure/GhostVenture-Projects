# OverHead Install Manager

OverHead Install Manager is a standalone Windows utility for installing, updating, or uninstalling OverHead Desktop, OverHead Cylinder Server, and OverHead Cylinder Client, and managing settings outside the app. A product picker lets the user select which product to manage and remembers the choice for the Windows account. When no choice has been saved, the Manager selects the only already-installed product when there is one; otherwise it follows the detected Windows edition. The Manager always applies the selected product's OS and hardware compatibility policy. Manual Manager launches show a Welcome screen. The Manager window cannot be resized or maximized, and text wraps within the layout; the legal notice scrolls on shorter displays.

A first-time OverHead installation requires separate affirmative Terms, Privacy, installation/data-handling, and draft-status acknowledgements plus the explicit **Yes, I agree** action before installation is enabled. **No, I do not agree** records no consent, cancels the first-install flow, and leaves installation blocked. The consent decision, notice revision, timestamp, and choices are encrypted with Windows account protection and saved locally without a name or email. A release metadata request is deferred until affirmative consent. Existing installations and consented update handoffs do not repeat first-install consent. For an in-app update handoff, Desktop writes a one-use, two-minute approval ticket encrypted with Windows account protection; the Manager checks the ticket against the parent process and selected product before it skips the replacement prompt. A bare command-line flag does not constitute update consent. GitHub publication dates are shown with release availability and in the update consent prompt.

The Welcome screen's legal text covers the product and installer's known local data handling, network requests, third-party providers, Windows changes, security limits, backup/recovery, update/removal effects, and unresolved commercial and legal topics. It links to the OverHead Legal Center. The existing Terms and Privacy materials are drafts pending qualified counsel review; the screen does not represent them as attorney-approved, complete legal advice, a liability shield, or a waiver of non-waivable rights. Counsel still needs to finalize the contracting identity/address, licensing/IP/open-source notices, privacy roles and individual-rights process, commercial terms, and jurisdiction-specific provisions.

The Manager identifies Windows ProductType, SKU, edition, build, and architecture. The product picker offers Desktop, Cylinder Server, and Cylinder Client, and does not bypass compatibility: Desktop install and update are limited to Windows 10/11 Home, Pro, and Enterprise workstations; Cylinder Client supports Windows 10/11 Home, Pro, Enterprise, and Education workstations; Cylinder Server install and update require Windows Server/IoT build 17763 or later. An already-installed product remains selectable for removal on an otherwise unsupported edition, provided its registration and uninstaller can be verified. Windows Education is supported for Cylinder Client only; editions outside the listed product groups are not currently supported. All three products require native x64, at least two logical processors and 4 GB RAM, Windows PowerShell 5.1 with Authenticode support, packaged runtime integrity, and free capacity for the download, complete local-data backup, staged data restore, and at least 1 GB or four times installer size on the installation volume. Unsupported hardware/software or insufficient/unknown space blocks install and update before download, backup, or removal. The packages bundle Electron, Chromium, and Node and declare no separate .NET, WebView, browser, plug-in, or extension installation. No external prerequisite is installed for this release. A future external prerequisite requires an approved source, integrity/signature policy, and consent-aware installer before the Manager can add it.

## What it manages

- Checks the selected product's matching stable release and verifies its `latest.yml`, published SHA-512, installer size, and installer Authenticode status. Desktop, Cylinder Server, and Cylinder Client use separate release asset names and feeds. Metadata requests and interrupted downloads retry transient failures. For an existing install, it asks before removing that product, verifies removal, installs the selected version into the same folder, and confirms installed version and trust status. It permits same-version repair/reinstall and blocks downgrades. A SHA-256 verified product-specific data backup is created first; data is compared after installation and restored to its pre-update state if anything changed.
- Uninstalls the selected product while keeping its local data by default. Optional data removal requires typing `REMOVE MY OVERHEAD DATA`; a verified backup is created first.
- Controls automatic update checks, Windows sign-in launch, and the Desktop data directory. Cylinder Server keeps its standard `%APPDATA%\OverHead Cylinder` data folder.
- Lists local backups and restores a selected backup only after integrity verification and a typed confirmation. Existing data is retained as a pre-restore copy.
- Shows installation progress and the published release date. After a successful installation, it verifies the installed version and data state, then closes automatically after 10 seconds.

Desktop, Cylinder Server, and Cylinder Client installations, update feeds, backup folders, and data roots are kept separate. The Manager does not copy Desktop data into Cylinder Server or remove another product during an install.

The Desktop package embeds the manager companion under the trust policy used for that build. The app copies it to `%LOCALAPPDATA%\OverHead Install Manager\Runners` and checks it before launch, so the manager can replace the Desktop install without running from inside the folder being removed. The installer does not launch OverHead after replacement; the manager verifies the preserved data before the user opens the updated app.

An already-installed build without the manager companion cannot perform this handoff. It must first be upgraded once with a manager-enabled Desktop installer; later GitHub updates use the consent-and-manager flow.

## Build the manager

Run:

```powershell
npm run install-manager:build
```

With no signing variables configured, the command builds a local unsigned portable utility under `release/install-manager`. It stays usable for local installation and settings work; before an update it checks the exact GitHub `latest.yml` SHA-512 and size, and validates the Authenticode signature when present. The UI labels this as a local unsigned build. This is not a publisher-signed release package.

The prior blank-window failure was traced to Electron returning `ERR_FILE_NOT_FOUND` for the bundled `app.asar/index.html` file URL. The UI now loads through an allowlisted `overhead-manager://` protocol that serves only its bundled HTML, CSS, and JavaScript files. The page's Content Security Policy denies resources by default, permits only local scripts, styles, and fonts (plus local/data images), blocks network connections and embedded content, and enforces Trusted Types with no custom policies. The package enables Electron ASAR integrity validation, requires application code to load from the integrity-checked ASAR, disables production developer tools and Node inspector/environment switches and extra `file://` privileges, and denies renderer permissions and navigation away from the local UI. The renderer uses context isolation, disabled Node integration, and sandboxing; IPC handlers accept requests only from the local Manager page. The fixed window is centered and constrained to the primary display work area; long UI text wraps, dense copy has larger type, and the legal notice can scroll on shorter displays. Its color palette follows the operating system's light or dark appearance preference. Startup load failures and renderer errors are recorded in `%APPDATA%\OverHead Install Manager\renderer-diagnostics.log`; IPC handler failures are recorded in `%APPDATA%\OverHead Install Manager\manager-errors.log`. These controls improve package integrity checks and reduce exposed renderer capabilities, but they do not make an unsigned executable tamper-proof. Someone with sufficient access to the computer can replace or patch it, and this local build does not prove publisher identity.

This workflow builds only a local unsigned Manager. It does not create, obtain, configure, or use code-signing certificates, private keys, or a signing authority. Certificate work and publisher-signed packaging are outside this Manager implementation task and require separate direction from the product owner.

The Desktop app reads `desktopDataRoot` from `%APPDATA%\OverHead Install Manager\manager.json` before selecting its Electron user-data folder. The manager copies and verifies data before changing this setting. Restart OverHead after moving its data directory.

The checked-in GitHub update workflow depends on compatible release metadata (`latest.yml`) and the matching `OverHead-Setup-<version>-win-x64.exe` asset. This local Manager build does not publish or update GitHub releases, and a successful local build does not mean the hosted Manager or Desktop installer has changed. Firebase hosting publication alone does not publish a GitHub release.

The local unsigned utility can be built and run as a development/testing package. Do not present it as a verified publisher release.

## Publish the standalone Manager to Firebase

Build the site into `website-next/out`, build the version-matched Manager with `npm run install-manager:build`, and update `website-next/public/downloads/SHA256SUMS.txt` and `website-next/public/downloads/OverHead-Install-Manager-SHA256.txt` with its SHA-256. To update only the Manager and its checksum routes, run `npm run deploy:manager -- --manager-only --plan` and review `release/install-manager/firebase-route-plan.json`; publish with `npm run deploy:manager -- --manager-only --publish`. The Manager-only plan preserves every other live route and Hosting redirect. The script checks the Manager checksum and signature status and verifies the site has not changed while files upload. An unsigned Manager is disclosed on the download page and must not be described as publisher-trusted.
