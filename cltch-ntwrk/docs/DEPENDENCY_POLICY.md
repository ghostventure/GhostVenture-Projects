# Dependency update policy

Dependabot opens weekly pull requests for npm dependencies under `cltch-ntwrk/` and GitHub Actions used by the repository. These updates are proposals for review; they are not merged or deployed automatically.

## Review each update

1. Read the package release notes and confirm the update is supported by the app's Node and Next.js versions.
2. Review both `package.json` and `package-lock.json`. Keep the lockfile changes generated by npm in sync with the manifest; do not hand-edit resolved versions or integrity hashes.
3. Run `npm ci`, the relevant smoke checks, and the production build from `cltch-ntwrk/`. Check the deployment configuration and user-facing behavior when the update affects runtime code.
4. Review transitive dependency changes and licenses when the package or its dependency tree changes materially.
5. Merge only after the pull request checks pass and a maintainer has reviewed the diff. Deploy through the normal release process.

## Security advisories

Run `npm audit` during dependency review and whenever a relevant security advisory is reported. Triage findings by affected package, reachable code path, available patched version, and severity. Record the disposition for findings that are not immediately fixed. Prefer a targeted compatible update and regenerate the lockfile with the package manager.

Do not run `npm audit fix --force` as an unattended repair. Force upgrades can cross major-version boundaries and break compatibility. If no compatible fix exists, document the exposure and mitigation, then plan a deliberate upgrade with focused tests.

## Automation limits

Automation may open update pull requests and run checks. It must not auto-merge dependencies, apply force upgrades, change Firebase rules or deployment settings, publish a release, or deploy the site. Those actions require normal human review and release validation.
