## Release verification

- `npm run build` passed locally under Node 22.23.3.
- `npm run predeploy:full` blocks release until the deployment environment supplies Square location/service identifiers, a private Firebase Storage bucket, SMTP configuration, and `SITE_BASE_URL`. Firebase runtime secrets are declared in `firebase.json` and must exist in Secret Manager.
- A partial production release completed to Firebase project `black-lion-media-studio` on October 25, 2026. Firebase Hosting and the Next.js server-rendered backend (`ssrblacklionmediastudio`, `us-central1`) were updated, and Firestore indexes were deployed. The deployment used a temporary config that bound only the existing `SESSION_SECRET`; the temporary config was removed after deployment.
- Live route checks after release returned `/` 200, `/api/me` 401 while signed out, and `/dashboard`, `/booking-manager`, and `/reset-password` 200. These checks confirm route availability and the expected signed-out response; they do not verify signed-in workflows or provider operations.
- Firestore rules and Firebase Storage rules were not part of this partial deployment. Square operations, file uploads/downloads, recovery email delivery, payment receipts, and authenticated production workflows remain unverified. The full `predeploy:full` gate still requires Square location/service identifiers, a configured Storage bucket, SMTP settings, and `SITE_BASE_URL`; the associated Square and SMTP secrets must also be available in Secret Manager.
- GitHub source is published on branch `codex/bls-centralization-ux-20261025`; this branch is not a Firebase deployment.
